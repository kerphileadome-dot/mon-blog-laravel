1. Introduction — Qu'est-ce qu'un blog et pourquoi ce projet ?

1.1 L'utilité d'un blog

Un blog (contraction de « web log », journal en ligne) est un site web dont le contenu principal est constitué d'articles publiés régulièrement, classés par date, thème ou catégorie. Contrairement à un site vitrine statique, un blog est dynamique : son contenu évolue dans le temps.

Pourquoi créer un blog ?
  • Partager des connaissances — Tutoriels, analyses, retours d'expérience.
  • Construire une identité professionnelle — Portfolio éditorial, expertise visible.
  • Créer une communauté — Commentaires, likes, favoris, échanges avec les lecteurs.
  • Améliorer le référencement (SEO) — Contenu frais indexé par les moteurs de recherche.
  • Centraliser ses idées — Carnet de réflexions structuré et accessible partout.

1.2 Le projet KerpheX Blog

KerpheX est un blog personnel professionnel développé avec le framework Laravel 13. Il répond à un besoin précis :

  • Seul l'administrateur peut publier, modifier et supprimer des articles.
  • Les visiteurs peuvent lire, commenter, liker et ajouter des articles en favoris.
  • L'interface est moderne, responsive et entièrement en français.
  • Le site fonctionne en local (Laragon) et en production (Railway).

Ce projet démontre la maîtrise d'une stack web complète : backend PHP, base de données, authentification, interface utilisateur, déploiement cloud et bonnes pratiques de développement.

3. Environnement de développement — Laragon

Laragon est un environnement de développement web tout-en-un pour Windows. Il fournit :

  • Apache (serveur web) — sert les fichiers PHP
  • PHP 8.3 — interprète le code Laravel
  • Composer — installe les packages PHP
  • Node.js — pour Vite et npm
  • Création automatique de virtual hosts — http://mon-blog.test

3.1 Installation locale — étapes réalisées

  1. Placer le projet dans C:\laragon\www\mon-blog
  2. composer install — télécharge Laravel et dépendances dans vendor/
  3. copy .env.example .env — fichier de configuration locale
  4. php artisan key:generate — clé de chiffrement unique (APP_KEY)
  5. Créer database/database.sqlite — base SQLite vide
  6. php artisan migrate — crée les tables (users, posts, comments…)
  7. php artisan db:seed — insère le compte admin et les articles démo
  8. php artisan storage:link — lien symbolique pour les images uploadées
  9. npm install && npm run build — compile CSS/JS dans public/build/
  10. php artisan serve — serveur dev sur http://127.0.0.1:8000
Pourquoi php artisan serve en plus de Laragon ?
Artisan serve utilise le serveur PHP intégré — pratique pour le développement rapide sans configurer Apache. Laragon reste disponible pour un environnement plus proche de la production.

4. Architecture globale du projet

Laravel suit le pattern MVC (Modèle — Vue — Contrôleur) :

┌─────────────┐ Requête HTTP ┌──────────────────┐ │ Navigateur │ ──────────────────► │ routes/web.php │ │ (Visiteur) │ │ (Routeur) │ └─────────────┘ └────────┬─────────┘ │ ┌────────────────────────┼────────────────────────┐ ▼ ▼ ▼ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │ Contrôleur │ │ Middleware │ │ Policy │ │ (logique) │◄───────│ (auth, admin)│ │ (autorisat.) │ └──────┬───────┘ └──────────────┘ └──────────────┘ │ ┌────────┼────────┐ ▼ ▼ ▼ ┌────────┐ ┌──────┐ ┌──────────┐ │ Modèle │ │Service│ │ Vue │ │Eloquent│ │BlogSet│ │ Blade │ └────┬───┘ └──────┘ └────┬─────┘ │ │ ▼ ▼ ┌──────────┐ ┌─────────────┐ │ SQLite │ │ HTML + CSS │ │ database │ │ (réponse) │ └──────────┘ └─────────────┘

Flux simplifié : L'utilisateur visite une URL → Laravel trouve la route correspondante → le middleware vérifie les permissions → le contrôleur exécute la logique (lit/écrit en base) → une vue Blade est rendue en HTML → le navigateur affiche la page.

6. Base de données et modèles de données

6.1 Pourquoi SQLite ?

SQLite stocke toute la base dans un seul fichier (database/database.sqlite). Pas de serveur MySQL à installer — parfait pour Laragon en dev et Railway en production (petit trafic).

6.2 Tables principales

TableColonnes clésUtilité
usersname, email, password, role, blockedComptes admin et visiteurs
poststitle, slug, content, category, tags, cover_image, views, publishedArticles du blog
commentspost_id, user_id, body, approved, parent_idCommentaires modérés avec réponses
likespost_id, user_id (unique)J'aime par utilisateur
favoritesuser_id, post_id (unique)Articles favoris
sessionsid, user_id, payloadSessions utilisateur (driver database)
cachekey, valueCache Laravel (driver database)

6.3 Relations Eloquent

Un User possède plusieurs Posts. Un Post a plusieurs Comments, Likes et Favorites. Les favoris lient User et Post en many-to-many. Les commentaires peuvent avoir un parent_id pour les réponses de l'admin.

6.4 Migrations — pourquoi chaque migration existe

  1. create_users_table — Table utilisateurs + sessions + reset password (base Laravel).
  2. create_posts_table — Structure des articles avec slug unique.
  3. create_comments_table — Commentaires liés aux articles.
  4. create_likes_table — Système de likes (initialement par IP, puis par user).
  5. add_role_to_users — Distinction admin / visitor.
  6. create_favorites_table — Système de favoris.
  7. add_blocked_to_users — Permet à l'admin de bloquer un visiteur.
  8. add_parent_id_to_comments — Réponses imbriquées aux commentaires.
  9. add_user_id_to_likes — Likes par utilisateur connecté.
  10. add_unique_constraint_to_likes — 1 seul like par user/article.
  11. add_tags_to_posts — Mots-clés CSV sur les articles.

8. Vues Blade et interface utilisateur

Blade est le moteur de templates Laravel. Il permet d'écrire du HTML avec des directives PHP simplifiées :

  • @extends('layouts.app') — hérite d'un layout parent
  • @section('content') — définit le contenu injecté dans le layout
  • @auth / @guest — affiche du contenu selon l'état de connexion
  • {{ $variable }} — affiche une variable échappée (sécurité XSS)
  • <x-post-card :post="$post" /> — composant Blade réutilisable

Le design KerpheX utilise une palette vert forêt (#0d7a55), fond crème (#f7f4ef), typographie serif Fraunces pour les titres et sans-serif Source Sans 3 pour le corps. L'interface est entièrement responsive (menu hamburger mobile, grilles adaptatives).

9. Authentification et gestion des rôles

9.1 Deux portes d'entrée

PortailURLQui peut entrer ?
Visiteur/loginTout le monde (inscription ouverte)
Administrateur/admin/loginUniquement les comptes role=admin

9.2 Rôles

  • admin — Publie des articles, modère, gère les utilisateurs, accède au panneau.
  • visitor — Lit, commente, like, favorise. Ne peut pas publier.

9.3 Google OAuth

Via Laravel Socialite, un visiteur peut se connecter avec Google. Si son email figure dans ADMIN_EMAILS (.env), il est automatiquement promu administrateur.

9.4 Sécurité

  • Mots de passe hashés avec bcrypt (jamais stockés en clair).
  • Protection CSRF sur tous les formulaires (@csrf).
  • Rate limiting sur le login (5 tentatives max).
  • Middleware CheckBlocked — déconnexion si compte bloqué.
  • PostPolicy — double vérification avant toute action sur un article.
  • HTTPS forcé en production.

10. Fonctionnalités détaillées

10.1 Articles

L'admin crée un article avec titre, extrait, contenu, catégorie, tags et image de couverture. Un slug URL-friendly est généré automatiquement (ex: coupe-du-monde-2026-tout-ce-quil-faut-savoir). L'article peut être publié ou en brouillon. Chaque lecture incrémente le compteur de vues.

10.2 Commentaires

Les visiteurs connectés postent des commentaires. L'admin peut les approuver, rejeter, répondre ou supprimer. L'auto-approbation est configurable dans les paramètres du blog.

10.3 Likes et favoris

Like = réaction rapide (cœur). Favori = marque-page personnel. Les deux nécessitent une connexion. Les icônes sur les cartes articles redirigent vers /login si non connecté.

10.4 Recherche, catégories et tags

La recherche parcourt titre, extrait, contenu, catégorie et tags. Les catégories et tags sont des champs texte sur les articles (pas de tables séparées — simplicité volontaire pour un blog de taille modeste).

10.5 Panneau admin

Dashboard avec 9 indicateurs (articles, vues, commentaires en attente, utilisateurs, likes, favoris…). Gestion complète du contenu, des utilisateurs, des médias et export CSV pour analyse.

11. Services, middleware et sécurité

11.1 BlogSettings — pourquoi un fichier JSON ?

Plutôt que de modifier la base de données pour chaque paramètre (nom du blog, pagination, modération auto), BlogSettings lit/écrit storage/app/blog_settings.json. L'admin modifie ces valeurs depuis le panneau sans toucher au code.

11.2 config/blog.php

Centralise la liste des emails administrateurs (ADMIN_EMAILS) utilisée par le seeder et Google OAuth.

12. Assets frontend — CSS, JavaScript, Vite

Vite compile resources/css/app.css et resources/js/app.js en fichiers optimisés dans public/build/. En développement, npm run dev recharge automatiquement les changements (HMR). En production, npm run build génère des fichiers minifiés avec hash dans le nom (cache busting).

Le layout utilise @vite(['resources/css/app.css', 'resources/js/app.js']) pour charger les bons fichiers selon l'environnement.

17. Conclusion

Le projet KerpheX Blog est une application web complète qui illustre le cycle de vie d'un produit numérique moderne :

  1. Conception — Blog éditorial avec rôles admin/visiteur.
  2. Développement — Laravel 13, PHP 8.3, SQLite, Blade, CSS custom.
  3. Environnement local — Laragon sur Windows pour développer et tester.
  4. Qualité — Tests PHPUnit, middleware de sécurité, policies d'autorisation.
  5. Déploiement — GitHub + Railway avec pipeline automatisé.
  6. Production — Site accessible mondialement avec HTTPS.

Chaque fichier du projet a une raison d'exister : les contrôleurs traitent les requêtes, les modèles représentent les données, les vues affichent l'interface, les migrations structurent la base, les seeders peuplent les données initiales, et les scripts de déploiement assurent que le site démarre correctement en production.
